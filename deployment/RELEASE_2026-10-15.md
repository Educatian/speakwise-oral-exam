# Production demo release: 2026-10-15

This branch records the source used by the verified production demo at https://speakwise-oral-exam.pages.dev (Pages deployment ebda5032). It starts at a9520b078a0ba912f3b62bc137307b103c24eeda, the legacy frontend deployed before the repair. The newer master development line and its Supabase Auth migration are separate; do not merge this branch over master without reconciling the authentication architecture.

## Reproduce

1. Run `npm ci` with a supported Node 22 runtime.
2. Copy `.env.example` to `.env` for the public data-bridge settings.
3. Run `npm run test:voice` and `npm run build`.
4. For this feature branch, configure the Microsoft Foundry server bindings listed in `.env.example` in the target Pages environment. Use the resource endpoint, server-side key, chat deployment and Foundry Speech endpoint. Separate audio model deployments can be used instead of Foundry Speech. The October release used OpenRouter.
5. Deploy `dist` to Pages project `speakwise-oral-exam`, production branch `main`, using Wrangler Pages deploy. Pages executes `public/_worker.js` for the same-origin AI endpoints.

For local AI requests use Wrangler Pages dev with `.dev.vars`; plain Vite dev only serves the frontend and does not supply the API proxy.

`deployment/data-worker/worker.mjs` is the source of the deployed data bridge, including the CORS and numeric decoding fixes. It requires the existing ARCHIVE D1 binding, AUTH_SECRET secret and PROJECT_REF configuration. Preserve these bindings when deploying. No database content or secret values are included here.

## Changes

- Replace broken legacy live-voice transport with proxied dialogue, transcription and speech synthesis.
- Await microphone initialization and complete prompt playback before recording.
- Reject silent input and empty interviews; retain transcripts when evaluation fails and offer Retry Evaluation.
- Validate evaluation score/feedback, shorten the opening, and correct the student rubric scale to /25.
- Keep API keys server-side. Repair data-bridge CORS and archived numeric score/timestamp decoding.

## Verification

Build/type check and six voice regression tests passed. On production, synthetic microphone input traversed the actual audio pipeline, generated a transcript and contextual follow-up, then manual end produced a persisted evaluation and student history. A separate instructor login opened the saved result and concept map. The production smoke result was 84; the preview result was 88. These are synthetic demo records.

An intentionally aborted evaluation produced a retry action without saving a zero result; retry succeeded. Ending an empty attempt produced no submission. Physical microphone/speaker quality, complete automatic multi-question termination and prolonged/mobile sessions were not tested.

Credentials stay in the user's Desktop handoff file and are excluded from Git.
